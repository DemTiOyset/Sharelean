# Sharelean_Umarov

UI-автотесты для учебного демо-магазина **ShareLane** (<https://sharelane.com>) — практическая работа
по дисциплине «Тестирование информационных систем».

Проект повторяет идею референса [Izteleuev_Daniel_Ruslanovich_Sharelean](https://github.com/Vashagod1/Izteleuev_Daniel_Ruslanovich_Sharelean.git)
(тот же стек: Maven + Selenium + TestNG, тот же сквозной сценарий покупки), но с исправленными
недостатками образца: вместо `System.out.println` используются настоящие проверки TestNG,
логин и пароль не захардкожены, а считываются со страницы ShareLane.

## Стек

| Компонент | Версия |
|---|---|
| Java | 21 |
| Maven | 3.9+ |
| Selenium WebDriver | 4.48.0 |
| TestNG | 7.10.2 |
| Браузер | Google Chrome (headless по умолчанию) |

Драйвер отдельно скачивать не нужно: Selenium 4 сам подбирает и при необходимости загружает
ChromeDriver через Selenium Manager.

## Что проверяет тест

Один сквозной e2e-тест `SharelaneE2ETest#shouldCompleteFullPurchaseFlow` проходит весь путь покупателя:

| № | Шаг | Проверка (assert) |
|---|---|---|
| 1 | Регистрация: ввод ZIP-кода `12345` | появляется форма создания аккаунта (ZIP прошёл валидацию) |
| 2 | Заполнение формы и нажатие `Register` | на странице есть текст `Account is created!` |
| 3 | Чтение сгенерированных ShareLane логина и пароля | e-mail совпадает с шаблоном `*@*.sharelane.com`, пароль не пустой |
| 4 | Авторизация на `main.py` | URL содержит `main.py`, есть приветствие `Hello`, доступно поле поиска |
| 5 | Поиск книги `War and Peace` | в результатах есть `War and Peace`, есть ссылка «add to cart» с `book_id` |
| 6 | Добавление книги в корзину | в корзине есть `War and Peace`, количество = 1 |
| 7 | Переход к оформлению заказа | открыта страница `Checkout`, есть блоки `Shipping`, `Payment` и данные заказа |
| 8 | Попытка оплаты тестовой картой `4242 4242 4242 4242` | ShareLane возвращает сообщение `Invalid card number...` (ожидаемое поведение) |

Шаг 8 — не «сломанный» тест, а осознанная проверка: у нас нет настоящей тестовой карты,
сгенерированной в [Test Portal](https://www.qatutor.com), поэтому сайт обязан отклонить оплату.
Это и фиксируется ассертом. Подробнее — в разделе «Ограничения».

## Быстрый запуск

```bash
# из корня проекта (папка Sharelean)
mvn test
```

Полезные варианты:

```bash
mvn test -Dheadless=false              # показать окно браузера
mvn test -Dtimeout.seconds=60          # увеличить таймауты ожиданий
mvn test -Dtest=SharelaneE2ETest       # запустить конкретный класс
mvn test -Dsurefire.suiteXmlFiles=...  # запуск через TestNG-сьют (если появится)
```

Результаты прогона: `target/surefire-reports/`
(`index.html` — отчёт в браузере, `emailable-report.html`, `org.example.sharelane.SharelaneE2ETest.txt`,
`testng-results.xml`).

Пошаговая инструкция по установке Java, публикации проекта на GitHub, приглашению

## Надёжность: почему тест не «флакует»

ShareLane устроен неочевидно, и это объясняет, почему код теста написан именно так:

1. **Каталог книг случаен.** Каждому новому аккаунту сайт выдаёт свой набор из двух книг
   (например, `book_id` 3 и 5), поэтому проверять наличие конкретной книги в каталоге нельзя.
2. **Поиск идёт по всей базе и только по полному названию.** Запрос `War and Peace` находит
   книгу `book_id=4` у любого аккаунта, а `War` или `The` — не находят ничего. Это проверено
   серией из 6 запусков на разных аккаунтах.
3. **После клика старая страница ещё мгновение остаётся в DOM.** Если проверять результат сразу,
   можно прочитать не обновившуюся страницу — классическая гонка в Selenium. Поэтому клики,
   которые отправляют форму, идут через `clickAndWaitForPageReload`: метод ждёт, пока старый
   `<body>` станет `stale` (браузер реально отрисовал новую страницу), и только потом выполняются
   проверки. Именно отсутствие такого ожидания заставляло первую версию теста иногда падать
   на шаге поиска.
4. **Вход в систему — двухшаговый.** ShareLane отвечает страницей `Redirecting...` и переходит
   на `main.py` через JavaScript, поэтому после логина тест ждёт появления приветствия `Hello`,
   а не просто перезагрузки страницы.

## Ограничения

1. **Оплата не проходит специально.** ShareLane принимает только карты, сгенерированные в Test Portal
   для конкретной сессии. Тест проверяет именно корректный отказ сайта.
2. **Аккаунт живёт недолго.** ShareLane удаляет тестовые аккаунты в начале следующего часа,
   поэтому каждый запуск создаёт нового пользователя с уникальным e-mail.
3. **Данные подменяются сайтом.** ShareLane намеренно заменяет введённые имя/пароль на случайные,
   поэтому тест не проверяет введённые значения, а читает сгенерированные со страницы.
4. **Нужен интернет** — тест работает против публичного сайта, а не локального стенда.
